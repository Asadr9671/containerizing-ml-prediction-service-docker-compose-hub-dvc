# Containerizing an ML Prediction Service with Docker, Docker Compose, Docker Hub and DVC

For the implementation explanation and a step-by-step Windows/VS Code terminal
guide, start with [WALKTHROUGH.md](WALKTHROUGH.md). It includes the existing workspace
setup, all run modes, assignment demonstrations, publishing, and troubleshooting.

MLOps Assignment 02: Meridian Diagnostics educational breast-cancer triage API.
This is an educational exercise, not a medical device. Dataset target 0 is malignant;
the API reports the probability of **class 0**, and labels it malignant when probability
is greater than or equal to the configured threshold.

## Reproduce from a fresh clone

Prerequisites: Python 3.12, Git, Docker Desktop with Linux containers (or Docker Engine),
and the `docker compose` plugin. Commands below use PowerShell; on Linux activate with
`source .venv/bin/activate` and replace `$env:GIT_SHA = ...` with `export GIT_SHA=$(git rev-parse HEAD)`.

```powershell
git clone https://github.com/Asadr9671/containerizing-ml-prediction-service-docker-compose-hub-dvc.git
cd containerizing-ml-prediction-service-docker-compose-hub-dvc
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-train.txt -r requirements-serve.txt -r requirements-dev.txt
dvc pull
dvc repro
python -m pytest -q -p no:cacheprovider tests
Copy-Item .env.example .env
$env:GIT_SHA = git rev-parse HEAD
docker compose up -d --build --wait
docker compose ps
python scripts/probe_api.py
```

`dvc-remote/` is intentionally committed for offline data restoration. Both original
569-row and corrected 539-row datasets are present in this local remote. Only DVC
pointers go into Git at `data/raw/`; raw CSVs, local cache and working model artifacts
are excluded. The final 30 original rows are removed for v2 without looking at model
results. All training and image builds use v2. Serialized artifacts in the local DVC
remote are generated by this repository; never load arbitrary untrusted joblib files.

## Local training and API

```powershell
python -m training.train --data-path data/raw/breast_cancer.csv --output-dir artifacts --model-version 1.0.0
python -m app.server --host 127.0.0.1 --port 8001
```

Open http://localhost:8001/docs, expand POST `/predict`, click Try it out, paste
`sample.json`, and Execute. `GET /health` returns `{"status":"ok"}` independently
of Redis. `/model/info` returns provenance, ordered features and training metrics.
All 30 numeric fields must be finite and nonnegative; missing, extra, string, Boolean
and negative values return 422. The model is loaded once at startup. Missing artifacts
fail startup with a clear log. Logs go to stdout. `/stats` returns an explicit disabled
state when Redis is not configured and 503 if configured Redis is unavailable;
predictions and health remain available during Redis outages. Only successfully
validated predictions increment the counter; invalid 422 requests are not predictions.

Training uses a stratified 80/20 split and shuffled five-fold stratified CV, all seed 42.
Both logistic regression and random forest include preprocessing in their Pipeline.
Selection uses mean CV malignant recall only, before held-out metrics are calculated.
The chosen model must achieve test malignant recall >= 0.95 or training exits nonzero.
Metrics are measured at threshold 0.5; changing the serving threshold does not rewrite
the recorded training metrics.

## DVC version switching and pipeline

```powershell
git checkout data-v1 -- data/raw/breast_cancer.csv.dvc
dvc pull data/raw/breast_cancer.csv.dvc
dvc checkout data/raw/breast_cancer.csv.dvc
python -c "import pandas as pd; print(len(pd.read_csv('data/raw/breast_cancer.csv')))"
git checkout data-v2 -- data/raw/breast_cancer.csv.dvc
dvc pull data/raw/breast_cancer.csv.dvc
dvc checkout data/raw/breast_cancer.csv.dvc
dvc repro
dvc repro
# Edit a hyperparameter in params.yaml, then:
dvc repro
dvc push
```

The first reproduction trains if dependencies or outputs changed; an unchanged run
skips training; a parameter edit invalidates the stage. Commit updated `dvc.lock`,
`params.yaml`, `metrics.json`, and `dvc-remote/` after intentional experiments.

## Images and runtime settings

```powershell
$env:GIT_SHA = git rev-parse HEAD
docker build --build-arg MODEL_VERSION=1.0.0 --build-arg GIT_SHA=$env:GIT_SHA -f Dockerfile.naive -t asad3390/breast-cancer-triage-api:naive .
docker build --build-arg MODEL_VERSION=1.0.0 --build-arg GIT_SHA=$env:GIT_SHA -t asad3390/breast-cancer-triage-api:1.0.0 .
docker run -d --name triage -p 18000:8000 asad3390/breast-cancer-triage-api:1.0.0
python scripts/probe_api.py --url http://localhost:18000
docker inspect --format '{{.State.Health.Status}}' triage
docker logs triage
docker run -d --name triage-threshold -p 18001:8000 -e DECISION_THRESHOLD=0.99 asad3390/breast-cancer-triage-api:1.0.0
```

The production image trains in a separate stage, copies only artifacts into the
runtime, runs as UID 10001, and uses Python's standard library for its healthcheck.
Training CSV, pandas, PyYAML, DVC and Git are absent from the final image.
Python and scikit-learn versions are pinned, and both training/serving dependency
files pin their full dependency set. `requirements-dev.txt` pins direct development
tools, including pathspec 0.12.1 for DVC compatibility.

| Variable | Default / purpose |
|---|---|
| MODEL_PATH | artifacts/model.joblib (model card must be beside it) |
| DECISION_THRESHOLD | 0.5; range 0 to 1 inclusive |
| LOG_LEVEL | INFO; stdout logging |
| REDIS_HOST | Unset standalone; redis in Compose |
| REDIS_PORT | 6379 |
| MODEL_VERSION | Build argument, 1.0.0; runtime env and image label |
| GIT_SHA | Build argument; runtime env and image label |
| DOCKERHUB_USERNAME | asad3390; Compose image namespace |
| IMAGE_TAG | 1.0.0 |
| API_PORT | 8000; configurable host port |

## Compose persistence and outage checks

```powershell
docker compose up -d --build --wait
python scripts/probe_api.py
Invoke-RestMethod http://localhost:8000/stats
docker compose stop redis
# /health and /predict still succeed; /stats reports 503.
docker compose start redis
docker compose down
docker compose up -d --wait
Invoke-RestMethod http://localhost:8000/stats
# Destructive only to this assignment's Redis data:
docker compose down -v
docker compose up -d --wait
Invoke-RestMethod http://localhost:8000/stats
```

Only the API publishes a host port. Redis uses service-name DNS and a named volume
with AOF enabled. A normal `down` retains that volume; `down -v` removes it and resets
the counter. API startup depends on the Redis healthcheck, while later Redis outages
do not prevent inference.

## Publish and verify without source code

Create public repository `asad3390/breast-cancer-triage-api` on Docker Hub and put
`DOCKERHUB_OVERVIEW.md` in its overview. Never commit credentials or `.env`.

```powershell
docker login -u asad3390
docker tag asad3390/breast-cancer-triage-api:1.0.0 asad3390/breast-cancer-triage-api:latest
docker push asad3390/breast-cancer-triage-api:1.0.0
docker push asad3390/breast-cancer-triage-api:latest
```

Before the clean-room check, stop/remove the assignment containers referencing these
images, then remove every local tag of the assignment images (including naive).
Do not use a global system prune. Create an empty folder and copy only
`docker-compose.hub.yml` and `.env` there. Run:

```powershell
docker compose -f docker-compose.hub.yml pull
docker compose -f docker-compose.hub.yml up -d --wait
docker compose -f docker-compose.hub.yml ps
docker image inspect --format '{{json .RepoDigests}}' asad3390/breast-cancer-triage-api:1.0.0
```

Use http://localhost:8000/docs to send a record; compare the pulled digest with the
registry tag digest. The Hub Compose file has no build section and needs no source
code or dataset. `latest` is an alias for our own release, never a third-party base tag.
